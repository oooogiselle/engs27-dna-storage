A hash table stores key-value pairs in an array of buckets, using a hash function to compute the index at which each key should live. When two keys hash to the same bucket, a collision occurs, and the table must resolve it, either by chaining (keeping a small list in each bucket) or by open addressing (probing for the next free slot). The expected cost of a lookup depends on the load factor, the ratio of stored items to buckets. With a good hash function and a load factor below about 0.7, lookups, insertions and deletions all take constant time on average.

Resizing is the price of this speed. When the load factor crosses a threshold, the table allocates a larger array, typically twice the size, and reinserts every item. A single resize costs time proportional to the number of items, but because the size doubles each time, the total cost of all resizes over n insertions is still O(n), so the amortized cost per insertion remains constant.
